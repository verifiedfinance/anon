# Publication result bundle

This directory documents the result artifacts that support the paper. It is a
source manifest for building a public bundle; it does not replace or modify any
experiment directory under `results/`.

## Evaluation sets and denominators

- **XBRLFiling:** all 600 questions in
  `data/multicompany_provable/data/provable_calcrequired.jsonl`.
- **FinanceBench:** all 67 questions in `data/numerical_questions.jsonl`.

No FinanceBench question is removed from the headline denominator. A row with
no parseable numerical candidate is an abstention. The shared FinanceBench
answer pool has three such rows. One textual response says
`coverage ratio is zero`, which the numerical parser conservatively leaves
unparsed; the other two are non-numerical narrative answers.

The exact operational definitions and formulas are in
[`scoring_policy.json`](scoring_policy.json). In brief:

- **TA:** a correct candidate accepted as `VERIFIED`.
- **FA:** an incorrect candidate accepted as `VERIFIED`.
- **TR:** an incorrect candidate rejected as `VIOLATED`.
- **FR:** a correct candidate rejected as `VIOLATED`.
- **AB:** no numerical candidate, `ABSTAIN`, `UNVERIFIED_FORMULA`, or any other
  non-decision status.

Precision is `TA / (TA + FA)`, decision accuracy is
`(TA + TR) / (TA + FA + TR + FR)`, coverage is
`(TA + FA + TR + FR) / n`, and abstention is `AB / n`.

Six FinanceBench questions require explicit unit, composite-answer, or
task-normalization handling. Their allowed numerical targets and rationales are
in [`manual_adjudications.json`](manual_adjudications.json). These rules are
candidate-specific: listing a question ID never makes every value for that
question correct. This fixes an earlier notebook pattern that could, for
example, score both 8,400 and 4,200 as correct on the same question.
The resulting count-derived metrics are frozen in
[`paper_metrics.csv`](paper_metrics.csv) and are independently regenerated by
`scripts/paper_scoring.py`.

Recompute and validate every canonical run and baseline from the repository
root with:

```bash
python scripts/paper_scoring.py
```

The command fails if a dataset is not exactly 600/67 unique IDs, a run has a
missing, extra, or duplicate ID, or a recomputed outcome disagrees with the
manifest. Use `--format json` for machine-readable output.

## Canonical baseline runs

Baselines contain `results.jsonl` but no separate SMT files. Outcomes are shown
as `TA/FA/TR/FR/AB` under the scoring policy above.

| XBRLFiling | LLM judge | `results/onepool/xbrl_judge` | 600/600 | 195/26/66/313/0 | 207,688 |

| FinanceBench | Direct LLM | `results/onepool/fb_none` | 67/67 | 46/18/0/0/3 | 32,497 |
| FinanceBench | LLM judge | `results/onepool/fb_judge` | 67/67 | 22/7/11/24/3 | 34,048 |
| FinanceBench | Judge + formula | `results/onepool/fb_judge_formula` | 67/67 | 34/13/5/12/3 | 34,010 |
| FinanceBench | Program of Thought | `results/onepool/fb_pot` | 67/67 | 40/4/14/6/3 | 46,700 |

These are one-pool comparisons. Every method reuses the exact `raw_answer`
text from the Claude Haiku 4.5 VeriFin run: all 600 XBRLFiling rows and all 67
FinanceBench rows match. When that source run has a null `claimed_value`, the
baseline loader reparses the same text. This recovers a numerical value for 7
XBRLFiling rows and 6 FinanceBench rows; it changes the parsed field, not the
generated answer. The three remaining FinanceBench rows are the abstentions
described above.

Judge + formula uses the source run's formula and grounded operands when both
are present. It falls back to the evidence-only judge for 7 XBRLFiling rows and
9 FinanceBench rows whose source artifact lacks a complete formula/fact pair.
For Program of Thought, `pot_program` stores only the first 300 characters for
compact audit metadata. The deterministic interpreter executed the complete
generated program before that preview was truncated.

The complete retrieved-evidence ablation is
`results/fb_detsmt_v2_haiku_agent_rag` (67 rows, 67 IDs, 67 SMT files;
2,870,435 bytes).

The notebook's LLM-SMT formalization ablation additionally uses
`results/mc_calc_qwen2.5-7b` and `results/mc_calc_llama3.1-8b`. Each has 600
rows, 600 unique IDs, and 600 current-status SMT files. These three ablation
runs are locked with the main bundle so every published notebook input is
present.

## SMT selection rule

For each result row, select exactly:

```text
smt/<row-id>_<row-status>.smt2
```

Every selected file exists and is non-empty. For decided rows, its contents
match the row's embedded `smtlib`. The FinanceBench Claude directory contains
121 SMT files for 67 IDs because 54 files preserve stale status-named versions
from earlier executions. Only the 67 files selected by the rule above belong in
the canonical public bundle. The original 121 files remain untouched.

## Known provenance issues

1. Older notebook cells point to
   `results/mc_calc_qwen3-30b_updated_schema_det_smt_schema_fixed_run1`, whereas
   final XBRLFiling figures use `results/latest/mc-qwen-30b-latest`. They are
   different runs. The latter is canonical here.
2. `results/latest/finbench-qwen-30b-latest` is also different from the newer
   FinanceBench run selected above. It is not a release alias.
3. Fin-o1's directory name says `30b`, while historical paper plotting code
   labeled it 8B. Public plotting code now uses the size-neutral `Fin-o1` label;
   see [`MODEL_IDENTITY_CAVEAT.md`](MODEL_IDENTITY_CAVEAT.md).
4. Existing `summary.json` files score agreement with internal solver labels.
   Those values are not the paper's answer-correctness metrics. Public paper
   metrics must be regenerated with `scoring_policy.json` and clearly named.
5. The directories under `results/latest/` are untracked in the research
   repository. A release builder must read the working tree, not only Git HEAD.

## Recommended public structure

```text
results/
  README.md
  manifest.json
  scoring_policy.json
  paper_metrics.csv
  xbrlfiling/
    baselines/<method>/results.jsonl
    verifin/<answer-model>/{results.jsonl,summary.json,smt/}
  financebench/
    baselines/<method>/results.jsonl
    verifin/<answer-model>/{results.jsonl,summary.json,smt/}
    ablations/haiku-retrieved-evidence/{results.jsonl,summary.json,smt/}
```

The publication builder emits a `run_manifest.json` beside every declared run
and baseline. It includes dataset and file hashes, relative source and release
paths, scoring policy, canonical SMT tree where applicable, and all recoverable
model or method provenance. Historical checkpoint, provider, decoding, or
configuration fields not embedded in the original artifacts remain explicit
`null` values with a stated metadata gap rather than being inferred.
